# BASTION VAULT — локальный зашифрованный PWA-сейф

**Версия:** 0.1 • экспериментальный прототип, не проходивший независимый аудит безопасности.

BASTION VAULT — автономный менеджер логинов и паролей для iPhone, работающий в установленном PWA. Приложение не требует регистрации, сервера для учётных данных или платного API. Файлы интерфейса можно разместить на обычном HTTPS-хостинге (например, GitHub Pages).

## ⚠ Перед использованием

Это **рабочая демонстрационная реализация**, но она **не заменяет проверенные менеджеры паролей для реальных важных аккаунтов до независимого аудита**. Сначала тестируйте вымышленными логинами и паролями.

- Автозаполнение паролей в **других приложениях iOS** из PWA технически недоступно: для него необходимо нативное расширение Credential Provider.
- Нажатие «Сгенерировать» меняет пароль **только в поле сейфа**, но не на сайте. Сначала измените пароль на самом сайте и убедитесь, что он принят, затем обновите запись.
- Буфер обмена виден другим приложениям, пока там находится скопированный пароль. В приложении есть отдельная кнопка очистки буфера.
- Без резервной копии данные могут пропасть при удалении PWA или очистке его веб-хранилища.
- Забытый мастер-пароль восстановить нельзя: серверной базы и механизма сброса нет.
- Если злоумышленник управляет устройством, установленным приложением, браузером или кодом сайта, никакое шифрование не гарантирует защиту.

## Установка с iPhone 17 — без компьютера

1. Скачайте ZIP-архив проекта в приложение **Файлы** и нажмите ZIP, чтобы распаковать.
2. Откройте **github.com** в Safari и войдите в GitHub.
3. Создайте **новый публичный репозиторий**, например `bastion-vault`. Публикуются **исключительно исходники приложения** — никогда не загружайте туда логины, мастер-пароль и экспортные копии. Для максимальной изоляции предпочтителен выделенный домен/origin, не разделяемый с другими GitHub Pages проектами.
4. Откройте репозиторий → **Add file → Upload files**. Загрузите в **корень репозитория** файлы `index.html`, `app.js`, `styles.css`, `sw.js`, `manifest.webmanifest`, `icon-192.png`, `icon-512.png`, `.nojekyll` (при необходимости README и SECURITY). Если в мобильном представлении GitHub кнопка не видна, в Safari используйте «Запросить настольный веб-сайт».
5. В GitHub откройте **Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save**.
6. После публикации адрес обычно имеет вид `https://ВАШ-ЛОГИН.github.io/bastion-vault/`. Откройте его в Safari, проверьте, что начинается с `https://`.
7. Нажмите кнопку **Поделиться** → **На экран «Домой»** → **Добавить**.
8. **Важно:** откройте приложение с новой иконки на экране «Домой» и **только в нём** создайте мастер-пароль и тестовые записи. Установленное PWA может использовать отдельную базу IndexedDB, независимую от вкладки Safari.
9. Создайте вымышленную запись, проверьте закрытие и повторное открытие, затем экспортируйте зашифрованную резервную копию и проверьте восстановление.

**Интернет нужен для первой установки и возможных обновлений.** После успешного кеширования оболочки сервис-воркером приложение может работать без сети. Внешних JS-библиотек, рекламы, аналитики и программных сетевых вызовов нет.

## Возможности версии 0.1

- Шифрование всего сейфа AES-256-GCM через Web Crypto.
- Ключ выводится из мастер-пароля через PBKDF2-HMAC-SHA-256, 600 000 итераций, случайная 128-битная соль.
- Отдельный криптографически случайный 96-битный IV при каждом новом шифровании.
- Шифротекст хранится в локальной IndexedDB.
- Генератор паролей 16–64 символов через `crypto.getRandomValues()`, с устранением смещения при выборе символов.
- Логины, пароли, URL, заметки, добавление/редактирование/удаление записей.
- Копирование логина и пароля, ручная очистка буфера обмена.
- Локальная проверка повторов паролей и слишком коротких паролей.
- Ручная блокировка, блокировка через 5 минут бездействия или после длительного нахождения в фоне.
- Зашифрованные резервные копии и их импорт с проверкой мастер-пароля.
- Смена мастер-пароля с новым ключом и новой солью.

## Технические ограничения и угрозы

| Риск | Последствия / меры |
| --- | --- |
| Утеря мастер-пароля | Расшифровать сейф нельзя |
| Удаление PWA, очистка хранилища, сбой браузера | Возможна потеря сейфа; регулярно делайте зашифрованный экспорт |
| Повторяющиеся/слабые мастер-пароли | Риск офлайн-перебора, несмотря на PBKDF2; используйте длинную уникальную парольную фразу |
| Буфер обмена | Другие приложения могут читать скопированные секреты; очищайте его вручную |
| Обновление кода на хостинге | Злонамеренное обновление может считать секреты после разблокировки; контролируйте репозиторий, защищайте GitHub 2FA, нужна проверка перед продакшеном |
| Взлом телефона, шпионское ПО, браузерная уязвимость | Шифрование диска не гарантирует безопасность расшифрованных секретов в памяти |
| Сторонняя PWA на iOS | Нет нативного Credential Provider / системного автозаполнения |
| Импорт старой копии | Заменяет текущий сейф после подтверждения; сначала экспортируйте актуальную копию |

Хостинг получает обычные запросы на **статические файлы интерфейса** и может видеть обычные сетевые метаданные, например IP-адрес. Приложение не посылает содержимое хранилища, однако абсолютную гарантию без утечек ни одна веб-среда дать не может.

## Основные файлы

- `index.html` — интерфейс и политика CSP
- `styles.css` — внешний вид
- `app.js` — криптография, локальная база, генератор и UI
- `manifest.webmanifest` — установка на домашний экран
- `sw.js` — офлайн-кеш статических файлов
- `icon-192.png`, `icon-512.png` — иконки
- `.nojekyll` — настройка GitHub Pages
- `SECURITY.md` — модель угроз

## Почему пока не Argon2id?

Для версии без внешних библиотек и без серверов применяется PBKDF2 через встроенный Web Crypto. Argon2id — более современная функция вывода ключа с защитой памятью, но её корректное внедрение требует тщательно проверенной реализации (как правило, WASM). Для реального продакшена стоит предусмотреть Argon2id, аудит кода, надёжную стратегию обновлений и защиту от потери данных.
