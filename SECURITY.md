# SECURITY — модель угроз BASTION VAULT 0.1

**Статус:** экспериментальный прототип. НЕ аудирован. Не использовать как единственное место хранения реальных важных паролей.

## Цели

1. Не хранить пароли и логины в открытом виде в persistent storage.
2. Не передавать секреты приложению-серверу, внешним API и аналитике.
3. Обеспечить шифрование записей под ключом, полученным из мастер-пароля на клиенте.
4. Предоставить экспорт исключительно зашифрованного файла.

## Структура данных

В `IndexedDB/bastion-vault-local-v1/encrypted/vault` сохраняется JSON-конверт:
`{format, version, iterations, salt, iv, data}`.
`data` содержит AES-GCM ciphertext + tag, полученный из JSON сейфа. Весь JSON записей, включая названия сервисов и заметки, шифруется. Мастер-пароль, сессионный криптографический ключ и расшифрованные записи не сохраняются в IndexedDB.

- Шифр: AES-256-GCM, случайный IV 96 бит на операцию, тег 128 бит.
- KDF: PBKDF2-HMAC-SHA-256, 600 000 итераций, случайная соль 128 бит на сейф/смену мастер-пароля.
- Дополнительные аутентифицируемые данные: `BASTION-VAULT/v1`.
- Генерация случайных данных: `crypto.getRandomValues`, для индексов используется rejection sampling.
- AES ключ: non-extractable Web Crypto `CryptoKey`.

## Чего нет

- Нет системной интеграции Face ID/Touch ID, Password AutoFill, Safari Credential Provider.
- Нет сервера, общего хранения, синхронизации или восстановления пароля.
- Нет полноценного аудита уязвимостей, проверки скомпрометированных паролей или оценки их энтропии.
- Нет защищённого канала вставки: буфер обмена остаётся менее защищённым.
- Нет противодействия вредоносному браузеру/ОС, злонамеренному владельцу хостинга или вредоносному обновлению приложения.
- Не заявляется полная защита от извлечения секретов из памяти браузера после разблокировки.

## Известные технические недостатки прототипа

- PBKDF2 — вычислительно затратная функция, но не memory-hard как Argon2id.
- Нет автоматической проверки цифровой подписи обновлений PWA и устойчивой цепочки поставок кода.
- Нет настоящей нативной защиты ключа через Secure Enclave.
- Нет защиты от параллельных изменений одного локального сейфа из нескольких вкладок.
- GitHub Pages для репозитория вида `username.github.io/repo/` разделяет веб-origin с другими Pages того же пользователя. Важно использовать выделенный origin без других недоверенных сайтов или отдельный домен.
- Не реализованы миграции/версионирование формата за пределами v1.
- Не проводились тесты на реальном устройстве iPhone 17, необходимы испытания Safari/iOS и сторонний аудит.

## Рекомендации перед реальным публичным запуском

Независимый аудит кода, KDF и модели ключей; подтверждение работы на актуальных iPhone; тестирование резервных копий, миграций и отказоустойчивости; проверка CSP и механизмов доставки обновлений; UX-тесты защиты от фишинга; защищённый канал сообщения об уязвимостях; продуманная политика приватности.
